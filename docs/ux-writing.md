# 모여락 UX 라이팅

화면 문구를 쓸 때 따르는 기준이다. 토스트 문구 규칙과 서비스 용어를 정리한다. (#197)

## 공통

- 해요체로 쓴다.
- 화면에 보이는 말을 쓴다. 사용자가 누른 버튼, 보고 있는 화면의 이름과 같은 말을 쓰고 개발 용어(클립보드, 확정 처리 등)는 쓰지 않는다.
- 가운데 점(·)을 쓰지 않는다. 두 대상을 묶을 때는 "날짜와 시간"처럼 풀어 쓴다.

## 용어

| 용어 | 뜻 | 쓰는 곳 |
| --- | --- | --- |
| 모임장 | 모임을 만든 사람 | 모임장 이름, 모임장에게만 보이는 기능 |
| 참여자 | 모임에 참여한 사람. 모임장도 포함한다 | 참여자 N/M, 참여자 목록 |
| 시간표 | 날짜와 시간의 틀. 기본값으로 만들어지고 모임장이 고친다 | 시간표 탭, "시간표 수정" 버튼과 시트 |
| 일정 | 시간표 안에 각자 칠한 가능한 시간 | "일정 추가하기 / 일정 수정하기" 버튼, 일정 입력 화면 |

- 모임장을 뺀 사람만 가리킬 때는 "다른 참여자"라고 쓴다. "팀장", "팀원", "팀"은 쓰지 않는다. (#176)
- "시간표 범위", "선택범위"는 쓰지 않는다. 시간표 수정 버튼 옆에 날짜와 시간이 함께 보여서 "시간표"만으로 무엇을 고치는지 알 수 있다.

## 토스트

토스트는 방금 한 행동의 결과를 알려 준다. 사용자가 한 줄을 읽고 "됐다 / 안 됐다 / 이렇게 하면 된다"를 바로 알 수 있어야 한다.

| 상황 | 토스트 | 알려 줄 것 | 형식 | 예 |
| --- | --- | --- | --- | --- |
| 됐을 때 | `toast.success` | 무엇이 됐는지 | [대상]이/가 [동작]되었어요 | 출발지가 추가되었어요 |
| 서비스 문제로 안 됐을 때 | `toast.error` | 무엇을 못 했는지와 다시 해 보라는 것 | [대상]을/를 [동작]하지 못했어요. 다시 시도해주세요 | 출발지를 추가하지 못했어요. 다시 시도해주세요 |
| 입력 때문에 안 됐을 때 | `toast.error` | 왜 안 되는지. 고칠 방법이 화면에서 보이지 않으면 방법까지 | 상황에 맞게 | 서비스 지역이 아니에요. 다른 곳을 선택해주세요 |
| 반응 없는 곳을 눌렀을 때 | `toast.message` | 어디를 누르면 되는지 | [버튼]을 눌러 … | 일정 수정하기를 눌러 가능한 시간을 바꿀 수 있어요 |

- 실패 문구의 [동작]은 사용자가 누른 버튼의 말을 쓴다. 예: "이동하기"를 눌러 실패하면 "이동하지 못했어요".
- 입력 문제는 사용자에게 필요한 정보를 고른다. 누른 것이 반영되지 않았다면 이유를("현재 참여 인원보다 적게 설정할 수 없어요"), 다음 행동이 보이지 않는다면 방법을("가능한 시간을 선택해주세요") 쓴다.
- 끝에 마침표를 찍지 않는다. 두 문장이면 사이에만 찍는다.
- 한 줄에 들어가야 한다. 디자인 시스템 Toast는 줄바꿈을 하지 않으므로, 아이콘을 포함해 375px 화면 양옆 20px 여백 안(335px)에 들어가게 쓴다. 메시지 글자는 아이콘이 있으면 279px, 없으면 303px까지다(Pretendard 14px Medium 기준).
- `src/toast-copy-static.test.ts`가 토스트 문구의 끝 마침표와 가운데 점을 검사한다. 한 줄에 들어가는지는 검사하지 않으니 새 문구는 직접 확인한다.
