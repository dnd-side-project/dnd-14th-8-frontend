# 화면 문구 전수 조사

UX 라이팅 정비의 1단계다. 서비스 화면에 나오는 문구를 모두 찾아 목록으로 만들고, 규칙을 정할 때 볼 숫자를 셌다. 이 문서의 숫자는 정비 전 상태의 기준이다. 문구는 고치지 않았다.

- 목록: [copy-inventory.csv](./copy-inventory.csv) (281행)
- 조사 때의 기준 문서: `docs/ux-writing.md`. #284에서 지웠고, 내용은 규칙 파일 [ux-writing/rules.json](../../ux-writing/rules.json)으로 옮겼다.

## 읽을 때 알아 둘 것 (2026-11-26)

- "규칙 후보"의 번호(W1부터 W23, C1부터 C16)는 조사 때 붙인 번호다. 규칙 파일의 번호(W01 등)와 다르다. 예를 들어 여기의 W13은 "해 주세요"이고, 규칙 파일의 W13은 "및"이다.

## 조사 기준

| 항목 | 값 |
| --- | --- |
| 조사한 날 | 2026-11-21 |
| 서비스 저장소 | `dnd-14th-8-frontend` main `c0e4c75` (#270까지 반영) |
| 디자인 시스템 | `@moyeorak/design-system` 0.11.0, `moyeorakui` main `189d05b` |
| 조사한 파일 | 서비스 `src` 아래 `.ts`, `.tsx` 189개(테스트와 스토리 99개 제외), `index.html`, `vite.config.ts`. 디자인 시스템 `src` 아래 36개 |
| 문구가 나온 파일 | 65개(서비스 59개, 관리자 화면 3개, 디자인 시스템 3개) |

줄 번호는 위 커밋 기준이다. 머지 전인 브랜치(`feat/271-place-in-result` 등)의 문구는 들어 있지 않다.

### 찾은 방법

1. TypeScript 컴파일러로 소스를 읽어 문구 후보를 뽑았다. JSX 안의 글자, 글자 리터럴, 템플릿 리터럴 가운데 한글이 있는 것과, 한글이 없어도 문구가 들어가는 속성(`placeholder`, `label`, `title`, `aria-label` 등)이나 JSX 자식에 놓인 것이다. 주석, `console.*`, import 경로는 뺐다. 서비스에서 372개(한글 289개), 디자인 시스템에서 6개(한글 3개)가 나왔다.
2. 리터럴이 아닌 값이 화면 글자로 들어가는 자리(`{dateLabel}`, `title={pageTitle}` 등)를 따로 뽑아, 그 값을 만드는 함수와 상수까지 따라가 읽었다.
3. 후보마다 코드를 읽고 화면에 나오는지, 어느 화면의 어느 자리인지 정해 목록에 적었다. 화면에 나오지 않는 후보 25개는 이유와 함께 제외 목록에 두었다(아래 "목록에서 뺀 것").
4. 스크립트로 두 가지를 대조했다. 목록의 모든 행은 적힌 파일과 줄에 그 문구가 있어야 하고, 뽑힌 한글 후보는 모두 목록이나 제외 목록에 있어야 한다. 둘 다 어긋난 것이 0개였다.

### 이 방법의 한계

- 종류, 자리, 화면, 어미, 오류와 버튼 분류는 코드를 읽고 판단해 정한 값이다. 기준은 아래에 적었지만 경계에 있는 행은 다르게 볼 수 있다.
- 화면을 띄워서 확인하지 않았다. 전부 코드 기준이다. 실제로 그 상태에 도달할 수 있는지, 글자가 잘리는지는 보지 않았다.
- 변수로만 조합되어 리터럴이 없는 글자(숫자, 날짜, 서버 값)는 후보로 뽑히지 않는다. 2번 단계에서 따라가 읽은 것만 "표기 형식"에 적었다.
- 이미지 안의 글자는 보지 않았다(`public/static/images/share.png`, `share-1.png`, 캐릭터와 그래픽 SVG). SVG 소스에 `<text>`는 없었다.
- 브라우저와 기기가 만드는 글자(위치 권한 창, 기기 공유 시트, 요일 이름 `Intl.DateTimeFormat("ko-KR")`)와 Radix 같은 라이브러리의 기본 문구는 범위 밖이다.

### 목록의 단위와 열

한 행은 코드에 적힌 문구 하나다. 같은 문구가 세 곳에 적혀 있으면 세 행이고, 삼항식으로 고르는 두 문구는 두 행이다. 상수로 빼서 여러 곳에서 쓰는 문구는 상수를 정의한 줄에 한 행만 두고 쓰는 곳을 비고에 적었다. 변수가 들어가는 문구는 틀을 그대로 적고 변수 자리를 `{이름}`으로 표시했다.

| 열 | 뜻 |
| --- | --- |
| 종류 | 버튼, 제목, 설명, 오류, 빈 화면, 토스트, 모달, 입력 안내, 기타. 한 행에 하나만 준다. 겹치면 오류, 빈 화면, 모달, 토스트 순으로 먼저 준다. 실패를 알리는 토스트는 오류다 |
| 자리 | 그 문구가 놓인 자리. 제목, 설명, 버튼, 라벨, placeholder, 도움말, 토스트, 접근성 이름 등. 모달의 제목은 종류가 모달이고 자리가 제목이다 |
| 화면 | 화면 또는 흐름. 여러 화면이 함께 쓰면 쉼표로 적었다 |
| 컴포넌트와 속성 | 예: `Modal.title`, `toast.error` |
| 어미 | 해요체, 합쇼체와 해요체 섞임, 명사형(-기), 명사(구), 끊긴 말(조사나 부사로 끝남), 해당 없음(숫자, 단위, 표기 형식) |
| 끝 부호 | 없음, 마침표, 물음표, 느낌표, 말줄임표 |
| 노출 | 화면, 스크린 리더 전용, 서비스 밖(브라우저 탭, 검색 결과, 카카오톡 대화방) |
| 대상 | 사용자, 관리자(`/admin` 화면) |
| 오류 문구 분류, 버튼 문구 분류 | 아래 4번과 6번 분석의 분류 |

### 표기 형식

글자가 아니라 표기라서 목록에는 일부만 있지만, 범위와 날짜를 적는 방식이 자리마다 다르다. 숫자는 형식을 보여 주려고 넣은 예시다.

| 대상 | 표기 | 위치 |
| --- | --- | --- |
| 날짜 | `11.5` | 일정 메인 요약(`date-summary.ts:9`) |
| 날짜 | `11.05` | 시간표 머리글(`timetable/index.tsx:82`) |
| 날짜 | `11월 5일 {요일}` | 최적 일정 카드. 요일은 서버가 준 글자를 그대로 붙인다 |
| 날짜 | `11월 5일 09:00 출발` | 개인별 루트 |
| 날짜 | `2026년 11월` | 달력 머리글 |
| 날짜 범위 | `11.5-11.7` (붙임표) | 일정 메인 요약 |
| 시간 범위 | `9:00-18:00` (붙임표) | 일정 메인 요약 |
| 시간 범위 | `{시작} ~ {끝}` (물결표) | 최적 일정 카드. 시작과 끝은 서버가 준 글자다 |
| 시간 범위 | `9시 ~ 18시` (물결표) | 시간표 수정 칩 3개 |
| 시간 범위 | `0 ~ 24시까지` (물결표와 "까지"를 함께) | 시간표 수정 도움말 |
| 시간 범위 | `09:00` `-` `18:00` (선택 상자 둘 사이 붙임표) | 시간표 수정 |
| 사람 수 | `참여자 3/5`, `3/5`, `참여가능(3)`, `현재 3명이 참여했어요` | 일정 메인, 최적 일정 카드 |
| 걸리는 시간 | `1시간 20분`, `평균 35분` | 중간지점 결과, 개인별 루트 |
| 거리 | `850m`, `1.2km`, `강남역에서 300m` | 개인별 루트, 주변 장소 |
| 돈 | `약 1,500원` | 개인별 루트 |

| 고유 이름 | 모여락(13), 카카오톡 |
| 바꿀 말이 마땅치 않은 말 | 새로고침(4), 초기화(4), 링크(7), 브라우저, PC, 홈 화면 |
| 장소 분류 | 스터디룸, 회의실, 식당, 카페 |
| 단위와 표기 | 명, 개, 위, 회, 원, 분, 시간, m, km |

범위로 빼는 것도 정해야 한다. 관리자 화면 20행, 스크린 리더 전용 18행, 서비스 밖 13행(메타와 공유 메시지)에 같은 규칙을 적용할지다.

## 조사하지 못했거나 판단이 애매했던 부분

- 관리자 화면(`/admin`)을 목록에 넣었다. 운영자만 보는 화면이라 "사용자 화면"에 드는지 애매해서, 넣되 `대상` 열로 나눴다. 분석 숫자는 서비스 258행 기준이다.
- 종류를 한 행에 하나만 주다 보니 경계가 있다. "중간지점을 찾지 못했어요"는 빈 화면 컴포넌트로 보여 주지만 오류로 분류했다. 실패 토스트 18개는 토스트가 아니라 오류로 셌다. 칩, 탭, 범례는 기타로 셌다.
- 불러오는 중 안내 9행은 기타로 셌다. 주어진 종류에 맞는 것이 없었다.
- "명사(구)"와 "명사형(-기)"를 나눴다. "보기", "가기", "닫기"처럼 "-기"로 끝나면 명사형으로 셌다. "더보기"와 "주변 살펴보기"(탭 이름)도 명사형으로 들어갔다.
- 오류 문구에서 "최대 4자까지 입력할 수 있어요"는 "어떻게 하면 되는지만"으로 셌다. 규칙을 알려 주는 문구라 방법으로 봤다.
- 버튼의 "막연함"은 문구만 보고 무엇이 일어나는지 알 수 있는지로 판단했다. "자세히 보기"와 "더보기"는 다르게 볼 수 있다.
- 화면에 실제로 나오는지 확인하지 못한 문구가 있다. "출발지를 선택해주세요" 2행, `schedule-main-optimal-content/index.tsx`와 `placeholder.tsx`에 겹쳐 있는 불러오는 중 문구, 값이 없을 때의 "출발 시간 선택", 모임장 이름을 못 찾을 때의 "모임장"이다.
- 토스트가 한 줄에 들어가는지, 긴 이름이나 긴 역 이름이 들어갔을 때 문구가 어떻게 보이는지는 보지 않았다.
- 서버가 주는 오류 메시지는 화면에 내보내지 않는다(`axios.ts`에서 `console.error`만). 그래서 백엔드 저장소의 메시지는 조사하지 않았다.
- 이미지 안의 글자, 브라우저와 기기가 만드는 글자, Radix 기본 문구는 조사하지 않았다.
